TensorRGBA CIFAR-10 testing notes
=================================

Purpose
-------
This note records the current CIFAR-10 airplane/ship example state and the
results observed while training and comparing Python and browser inference.
The model is a 32x32 RGB conditional GAN. These results are not a claim that
its generated images are sharp or photorealistic.

Training run
------------
Run from examples/cifar10/train:

  python train.py --epochs 20 --batch-size 64 --lr 0.0002 --noise-dim 128 --cpu-threads 2

Observed result:

- Device: CPU
- Training completed for 20 epochs.
- Checkpoints were written at epochs 10 and 20, and as
  checkpoints/airplane_ship_gan/airplane_ship_gan_final.pt.
- Final reported losses: D=0.4293, G=1.8523.

Export commands
---------------
Run from examples/cifar10/train:

  python export_float32.py --checkpoint checkpoints/airplane_ship_gan/airplane_ship_gan_final.pt --output ../cifar10_float32.png
  python export_int8.py --checkpoint checkpoints/airplane_ship_gan/airplane_ship_gan_final.pt --output ../cifar10_int8.png

Both exports completed. The float32 model PNG was 660x660 RGBA and the int8
model PNG was 330x330 RGBA. Each contains 434563 model values.

Checks that passed
------------------
- python -m py_compile train.py model.py export_float32.py export_int8.py
- node --check on the CIFAR model loader and inference JavaScript
- Pillow opened and verified both exported PNG files.
- In Python, model.forward and an explicit sequence of the same generator
  layers produced identical outputs for one fixed noise vector and class 0
  (maximum absolute difference: 0.0).

Python-to-JavaScript inference discrepancy
------------------------------------------
A separate end-to-end comparison loaded cifar10_float32.png through the
JavaScript PNG decoder and compared browser inference with PyTorch using the
same fixed 128-element noise vector and class 0. The reported maximum absolute
output difference was 0.013406217.

A layer-by-layer harness reported much smaller maximum differences:

- Fully connected layer: 5.96e-8
- First BatchNorm/ReLU block: 4.77e-7
- First transposed convolution: 1.91e-6
- Second BatchNorm/ReLU block: 3.10e-6
- Second transposed convolution: 9.54e-7
- Third BatchNorm/ReLU block: 2.38e-6
- Final transposed convolution: 1.30e-6
- After tanh: 1.29e-6

These results conflict with the end-to-end comparison. Another combined harness
also found that Python forward and Python manual output matched exactly, while
JavaScript output differed by 0.013406217. The layer-level result therefore
must not be treated as proof that the public JavaScript inference path matches
PyTorch. The cause was not identified in this work; do not describe parity as
fully verified until the test discrepancy is reproduced and resolved.

Suggested investigation
-----------------------
1. Reproduce the comparison against the committed float32 PNG and final
   checkpoint using one persistent test harness.
2. Compare the exact input vector, labels, decoded weight array, and output
   tensor in that same process.
3. Keep the public functions createGenerator and generateCifarImage in the
   comparison; compare against PyTorch before and after each layer.
4. Check array lengths, offsets, tensor layouts, and output channel order.

Current code and artifacts
--------------------------
- Model and trainer: examples/cifar10/train/model.py and train.py
- Exporters: examples/cifar10/train/export_float32.py and export_int8.py
- Browser implementation: examples/cifar10/web/load_model.js and inference.js
- Exported models: examples/cifar10/cifar10_float32.png and cifar10_int8.png

This note describes observed tests only. It does not claim that the
Python/JavaScript numerical discrepancy has been fixed.
